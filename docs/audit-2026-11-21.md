# Hustle Builder family and customer flow audit

Date: November 21, 2026. Release: PR #120.

## Repairs

| Area | Finding | Result |
| --- | --- | --- |
| Family sign-out | Signing out removed the active local business and earnings rather than keeping an owner recovery copy. | Archive local work privately before sign-out, restore it only after the owning parent signs in, and keep the session/work when sign-out fails. |
| Private screens | Old request responses and identity checks could finish after sign-out. Existing booking actions and calendar URLs stayed in the DOM. | Clear private controls and calendar URLs; reject responses from an earlier private-view generation. |
| Multiple children | Local build copies reused a cloud payload that drops large photo sets; some storage failures were ignored. | Preserve full local photos and separate earnings per build. Refuse switching/new-page actions when the current build cannot be saved. |
| Device transfer | A website draft link could be mistaken for a full business backup. | Explain that job/money records stay on the device, warn when photos exceed the cloud draft limit, and provide a backup-file action. |
| Booking inbox | Requests polled every eight seconds, including background tabs; errors silently disappeared. | Poll every 30 seconds only on the visible jobs screen, avoid overlapping refreshes, provide manual refresh/sign-in and useful error recovery. |
| Request actions | Duplicate actions, silent failures, repeated confirmation buttons and a parent-facing payment button confused the workflow. | Lock actions while saving; confirm cancellation; show status/error feedback; remove terminal actions and offer a customer payment link to copy after completion. |
| Advance bookings | Request cleanup ran 30 days after arrival, although the calendar allows advance bookings. | Per the owner's choice, retain until 30 days after scheduled work, or arrival if undated. Pet-care ranges also retain through the last away day. Cancellation links follow their request; calendar files remain available through future work. Update the published notices and PostgreSQL/file cleanup. |
| Customer recovery | Saved copies offered a generic booking email; a failed response could hide the request copy. | Direct saved copies to their live form when available. Clearly identify draft previews. Keep a request copy after failed/uncertain delivery and preserve the existing idempotent retry ID. |
| Pet care | Missing/reversed away dates and invalid pet counts could be submitted. | Validate dates and a whole pet count of 1–20 before generating/submitting a request. Stop sending stale hidden away-date values. |
| Flyers | Entering Flyers reset a selected design. | Keep the family's selected flyer and poster styling. |
| Maps | The embedded Google map was blocked by the site's own content security policy. | Offer working map/directions links without an empty embedded frame. An address goes to Google when the user opens the link. |
| Style customization | Curated Hustle/Neighbor pages exposed lighting/art controls that did not alter those designs. | Show the relevant controls and explain each curated style; retain legacy controls for designs that use them. |
| Account controls | Pause/offline success messages were immediately erased, and network failures lacked feedback. | Preserve success messages, disable in-flight controls, and explain failed actions. |
| Publish/delete | Repeat clicks could overlap; account deletion used an indefinitely armed button with incomplete scope copy. | Lock publishing while it runs; show an explicit full-family deletion dialog and clear private views on success. |
| Email recovery | Hourly retry could outlive a sign-in code's 20-minute validity. | Keep immediate delivery and retry queued mail every ten minutes, preserving expiration and deduplication rules. |
| Keyboard | Dialog focus could leave the active modal. | Trap Tab/Shift+Tab while a dialog is open and return focus when it closes. |

## Verification

Release gates are the repository's complete `npm test`, `npm run test:stress`, and `npm run test:browser` suites. Browser checks run in GitHub Actions against isolated local stores with fake delivery/payment mode; production checks use anonymous browsing only.

- Unit/security/storage coverage includes real SQL execution with PGlite, atomic writes, session and origin isolation, payment/refund/webhook deduplication, 14-day family trials, migration, request retention, lost connectivity and full-storage recovery.
- All 29 synthetic stress scenarios pass, including 400 concurrent public reads and concurrent family booking/publishing scenarios. These measurements do not establish production Vercel capacity.
- Existing browser coverage checks actual publishing, booking, trial renewal/payment return, sibling pages, all builder steps at phone width, 48 curated service/style/width render combinations, offline drafts and artwork, and published-page isolation.
- The added browser walkthrough covers the parent landing at 320/390/768/1366 pixels, returning-parent sign-in, photo upload, job earnings, valid completed PDF/PNG downloads, saved-build switching, failed/successful sign-out and owner restore, booking action errors and cancellation, pause/resume, modal focus and customer retry recovery.
- Existing source art, icons, and the HEIC helper remain byte-identical; the preservation suite verifies their hashes.
- Previous parent spacing and copy changes remain: Three steps follows the trial paragraph, the standalone Sam disclaimer is removed, and the site does not restrict yard work to hand tools. No ladder/gutter offerings are introduced.

## Practical limits

Real card charges, production customer requests, and real email delivery were not generated during this audit. Provider availability and recipient inbox placement still depend on Stripe, Resend, and the customer's network.

A draft link is not a full business backup. Cloud draft payloads still omit photo sets over the existing size limit; full local copies now retain them and the transfer screen explains the limit. Use the built-in backup file with photos to move the website, photos, and local money/job log together. Existing published customer pages retain their stored HTML until the parent republishes an update.

Offline photo caching can help after artwork has loaded successfully. It cannot bypass hospital Wi-Fi filtering on a first visit or guarantee another device's network behavior.
